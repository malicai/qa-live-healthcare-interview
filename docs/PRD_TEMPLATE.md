# PRD 模板(Feature PRD Template)

> 本模板依据 `.asdm/toolsets/prd-builder/spec/feature-prd-spec.md` 制定,适用于本项目所有特性需求。
> **使用方法**:复制本文件为 `docs/<特性名称>-PRD.md`,替换所有 `<...>` 占位符,删除不适用的小节,保留章节编号。
> 项目开发规范见根目录 [CLAUDE.md](../CLAUDE.md) 与 `docs/server-coding-standards.md`、`docs/web-coding-standards.md`。

## 7. 任务拆分(Task Breakdown)

### 7.1 拆分原则

- **粒度**:每个任务控制在 1–2 人时(约等于 AI 5–10 分钟)
- **独立性**:尽量减少任务间依赖,可并行的任务并行
- **可测试性**:每个任务都有明确的验收标准与确定性验证命令
- **数量限制**:单个特性建议 **≤ 10 个任务**;超过 10 个必须拆分为子特性

### 7.2 任务清单

| Task ID | 任务名称 | 描述 | 依赖 | 验收标准 / 验证命令 | 工作量 | 状态 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| TASK-001 | `<任务名称>` | `<做什么>` | 无 | `<如:./mvnw test 通过>` | `1h` | TODO |
| TASK-002 | `<任务名称>` | `<做什么>` | TASK-001 | `<如:npm run build 通过>` | `1h` | TODO |

### 7.3 任务状态

| 状态 | 含义 |
| ---- | ---- |
| TODO | 待开始 |
| IN PROGRESS | 进行中 |
| DONE | 已完成并通过验证 |
| BLOCKED | 被阻塞(需在实现说明中注明原因) |
| CANCELLED | 已取消 |

## 附录 A:AI 使用指南

使用本模板让 AI 编写 PRD 与执行开发时,按以下步骤进行:

1. **提供上下文**:告知 AI 特性需求,并要求其阅读 `CLAUDE.md`、`docs/server-coding-standards.md`、`docs/web-coding-standards.md` 及相关代码
2. **复制模板**:生成 `docs/<特性名称>-PRD.md`,填写第 1–6 节
3. **拆分任务**:按第 7 节拆分,每个任务附验证命令;检查任务数是否 ≤ 10
4. **评审确认**:提交 PRD 给需求方评审,确认后再进入开发
5. **按任务执行**:逐条实现任务,完成后更新状态与验证结果
6. **收尾**:状态改为 `COMPLETED`;补充实现说明与测试报告

**提示词示例:**

```text
请阅读 CLAUDE.md 与 docs/PRD_TEMPLATE.md,按模板为「<特性名称>」编写
docs/<特性名称>-PRD.md。要求:用户故事含验收标准;功能需求编号 REQ-xxx;
任务拆分每个任务 1-2 小时并附确定性验证命令,任务数不超过 10 个;如超过请给出子特性拆分方案。
```

## 附录 B:填写规范

- 所有占位符 `<...>` 必须替换,不得保留在最终 PRD 中
- 需求、任务、用户故事必须可追踪:REQ → Story → TASK 双向对应
- 成功标准与验收标准必须可度量,避免「体验良好」「尽快」等模糊表述
- 状态值固定为模板定义值,不得自造
- 文档语言保持简体中文,代码、命令、字段名保持英文
